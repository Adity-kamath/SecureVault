1. System Architecture & High-Level Module Overview

SecureVault isolates responsibility across 6 distinct project directories. Every request enforces authenticated sessions, input validation, cryptographic confidentiality, and audit tracking.

┌─────────────────────────────────────────────────────────────────────────────┐ │ 🌐 FRONTEND (React 18 + Vite) │ │ • Pages (Login, Vault, Health, Admin) • Contexts (Auth JWT) │ │ • Components (Generator, Modals, Strength Meter) • Axios Services │ └──────────────────────────────────────┬──────────────────────────────────────┘ │ HTTPS / JSON REST (Bearer JWT) ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ ⚙️ BACKEND (Node.js + Express.js) │ │ • Middleware (JWT Verification, RBAC, Validation, Central Error Handling) │ │ • Controllers (Auth, Credentials, Sharing, Health, Admin) │ │ • Crypto Engine (AES-256-GCM cipher/decipher, IV generation, zxcvbn) │ └──────────────────────────────────────┬──────────────────────────────────────┘ │ Mongoose ODM / TLS ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ 🗄️ DATABASE (MongoDB Engine) │ │ • Collections: users, credentials, sharedaccesses, auditlogs │ │ • Embedded MongoDB Memory Server fallback for instant zero-config setup │ └─────────────────────────────────────────────────────────────────────────────┘
Zero-Knowledge Security Invariant: System administrators possess governance authority (suspending users, setting access tiers, inspecting audit logs), but the cryptographic architecture prevents administrators or databases from decrypting passwords of accounts they do not own.

6. End-to-End Request & Security Lifecycle

How Data Flows Through The System:
  1. UI Action: User enters a password in CredentialFormModal.jsx; LiveStrengthMeter.jsx computes entropy score (0–4) locally.
  2. API Transmission: credentialService.js sends a POST /api/credentials request with the Bearer JWT token in the Authorization header.
  3. Auth Verification: auth.js middleware decodes the JWT, validates user active state against the User model, and attaches req.user.
  4. AES-256-GCM Encryption: credentialController.js passes the plaintext secret to crypto.js, which generates a fresh 16-byte random IV, creates a Galois Counter Mode cipher, and extracts a 16-byte authentication tag.
  5. Database Persistence: Only ciphertext, IV, and auth tag are written to MongoDB via Credential.js. Plaintext is discarded from memory.
  6. Audit Logging: auditLogger.js writes an immutable record to AuditLog.js recording user identity, action (create), credential title, client IP, and timestamp.
  7. On-Demand Decryption (Reveal): When an authorized user requests reveal, credentialController.js verifies ownership or SharedAccess.js permissions, decrypts the ciphertext using the stored IV and auth tag, and streams the decrypted password back to the client.
